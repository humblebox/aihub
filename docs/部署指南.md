# 部署与运维

## 安装

在全新 Ubuntu 22.04/24.04 x86_64 克隆仓库，执行：

```bash
sudo bash scripts/install.sh --host 公网IPv4或域名
```

自定义管理员用户名可用 `sudo AIHUB_ADMIN_USER=yourname bash scripts/install.sh --host ...`。密码、FRP 令牌和核心控制密钥独立生成。固定安装目录为 `/opt/aihub`，有现存 AIHub 时拒绝覆盖。中途下载失败可能留下部分文件，脚本不会擅自删除运行数据；修复网络后先人工检查已创建目录再决定清理或恢复，不要在生产主机强制重跑。

版本：Harness 0.2.2-rc.5、dsh-remote 0.8.71、Node 24.22.2、pnpm 10.11.0、FRP 0.71.1、Mihomo 1.19.29、Zashboard 3.30.0。Harness 仅使用 npm 全局安装，由 systemd 启动同一份程序，不使用虚拟环境。官方组件依赖由 Harness 包管理，不再单独安装第二份运行目录。npm 使用固定顶层版本及 `--legacy-peer-deps`；全局安装的间接依赖不由本仓库锁文件固定。GeoIP 使用上游 latest，下载仍需访问官方网络。Node 下载额外校验官方 SHA256 清单。

安装器不配置模型密钥、不导入订阅、不复制既有设备、不替换其他 Nginx 站点，也不更改云安全组或 UFW。需要自行确认443未被其他站点占用，并放行22、443、7000。HTTPS 默认自签名证书，有域名时可另行接入可信证书。

## 服务与端口

| 服务 | 功能 |
| --- | --- |
| nginx | HTTPS及统一认证门禁 |
| aihub-login | 密码登录、修改密码、原生会话交换，回环3081 |
| aihub-harness | AI网页、模型和插件，回环3080 |
| aihub-enrollment | 受限 Unix socket 设备注册和代理管理 |
| aihub-frps | 设备入站连接，公网7000；SSH映射仅回环20000–20999 |
| aihub-clash | 可网页关闭的代理核心，回环7890/9090 |
| aihub-clash-update.timer | 每小时更新当前配置 |

账号数据：`/var/lib/aihub-login`；Harness 与远程记录：`/var/lib/aihub/.dsh`；代理配置：`/var/lib/aihub-clash`；FRP：`/etc/aihub/frps.toml`；Nginx：`/etc/nginx/sites-available/aihub`；部署主机信息：`/etc/aihub/deployment.json`。

```bash
sudo systemctl status aihub-harness aihub-login aihub-frps aihub-enrollment --no-pager
sudo nginx -t
sudo python3 scripts/healthcheck.py --host 你的主机
```

健康检查使用初始密码文件，只用于初次安装；修改密码后不要用旧文件验证登录。日志、账号和备份可能含敏感信息，勿提交。

## 终端停止、启动和重启 Harness

以下命令在部署 AIHub 的云服务器终端执行；如果当前在其他电脑，请先通过 SSH 登录云服务器。

```bash
# 停止 DeepSeek Harness
sudo systemctl stop aihub-harness

# 启动 DeepSeek Harness
sudo systemctl start aihub-harness

# 重启 DeepSeek Harness
sudo systemctl restart aihub-harness

# 查看运行状态，直接输出后退出
sudo systemctl status aihub-harness --no-pager

# 实时查看日志，按 Ctrl+C 退出查看，不会停止服务
sudo journalctl -u aihub-harness -f

# 查看最近 100 条日志
sudo journalctl -u aihub-harness -n 100 --no-pager
```

停止或重启会中断当前 AI 任务，期间网页 AI 功能不可用。FRP 隧道由独立的 `aihub-frps` 服务及目标设备的 `frpc` 服务维持，停止 Harness 不会停止这些隧道。

安装时已设置 Harness 开机自动启动。`stop` 只停止本次运行，不取消开机启动；手动停止后可用 `start` 恢复，服务器下次重启仍会自动启动。不要在 systemd 服务运行期间另外手动启动一份 Harness，以免端口冲突。

## 账号与权限

当前为单管理员工作环境，不提供不同用户的文件、会话或机器隔离。统一登录使用 scrypt、签名Cookie、表单防伪令牌和失败次数限制。登录服务本机读取 Harness 启动令牌并交换原生会话；外部不需要令牌链接。

设备首次下载和注册复用 SSH22，生成短期受限密钥。目标设备长期 FRP 使用共享服务令牌，撤销首次接入命令不等于撤销已经在线的设备。设备 SSH 账号权限就是可操作范围，工作区目录不是系统沙箱。

## 备份与更新

全局程序目录为 `/opt/aihub/node-v24.22.2-linux-x64/lib/node_modules/@deepseek-ai/dsh`；`dsh`、`node`、`npm`、`npx` 在 `/usr/local/bin` 提供命令入口。服务保持使用 `aihub` 账号和 `/var/lib/aihub/.dsh` 数据目录；不要以 root 直接运行不带配置的 `dsh` 代替服务，否则会使用 root 的另一份用户数据。

`dsh-remote` 等第三方插件由 `/var/lib/aihub/.dsh/profiles/web` 中的 pnpm 管理，不链接到全局插件目录。`package.json`、`pnpm-lock.yaml` 和实际安装版本必须一致，否则网页更新无法验证精确回滚来源。2026年11月24日已将远程插件恢复为 profile 内安装的 0.8.71，并生成对应锁文件。全局 Harness 与 profile 插件是主程序及扩展的关系，不是两份 Harness，也不是虚拟环境。

更新前等当前任务结束，先备份下文所列目录及全局程序，然后在云服务器执行（版本号按需要替换）：

```bash
sudo systemctl stop aihub-harness
sudo /usr/local/bin/npm install -g @deepseek-ai/dsh@0.2.2-rc.5 --allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs
sudo systemctl start aihub-harness
sudo systemctl status aihub-harness --no-pager
```

更新失败时先处理安装错误或恢复备份，不要继续启动损坏的安装。更新后检查登录、模型、插件、远程设备及命令执行。此命令只更新 Harness；第三方插件仍通过现有 profile 管理，不会随之统一升级。统一登录、设备接入、FRP、Clash、模型隧道及自定义脚本继续保留原有位置和 systemd 服务。

更新前备份 `/var/lib/aihub`、`/var/lib/aihub-login`、`/var/lib/aihub-clash`、`/etc/aihub`、Nginx及systemd配置，并限制备份读取权限。不要复制整个新 profile 覆盖用户已增加的提供方。当前安装器是首次安装工具，不提供自动升级、卸载或无损回滚承诺。

修改主机名时需同时更新部署JSON、登录服务 `AIHUB_PUBLIC_ORIGIN`、Harness trustedHosts、Nginx server_name和证书，并重新生成受影响的设备接入命令。

## 已知限制与验证

`dsh-remote 1.4.1` 的 OpenSSH 后端缺少交互终端 `shell()` 接口，表现为新建终端返回 `this.delegate.shell is not a function`。云端已使用 `scripts/adapt_remote_terminal.py` 补充 PTY 适配，保留 SSH 别名、认证及严格主机校验。部署脚本到 `/opt/aihub/adapt_remote_terminal.py` 后执行 `sudo python3 /opt/aihub/adapt_remote_terminal.py`，再重启 Harness。适配仅允许 1.4.1；插件重装可能覆盖修改，升级其他版本时应先确认上游是否已修复，不要强行套用。

新版 OpenSSH 公钥文本文件是 `/var/lib/aihub/.dsh/remote-workspaces/known_hosts`，与原生后端 `known_hosts.json` 分离。缺少公钥时应从已经验证的 SSH 主机记录迁移，不能通过关闭严格校验解决。设备接入脚本已按插件主版本选择对应路径。

交互终端还要求目标机器的 AIHub 专属 `authorized_keys` 条目允许 PTY。新接入使用 `restrict,port-forwarding,pty`；旧设备的 `restrict,port-forwarding` 会拒绝 PTY。已接入设备需按对应密钥单独迁移，不应修改无关密钥或取消其他限制。Windows、安卓的模板已更新，但未实机验证交互终端。

旧 Linux／安卓设备可以在云服务器使用自动脚本，无需逐台登录编辑文件：

```bash
# 先检查所有旧设备，不修改
sudo python3 /opt/aihub/enrollment/enable_pty.py --all
# 为所有在线且符合标准接入格式的旧设备启用 PTY
sudo python3 /opt/aihub/enrollment/enable_pty.py --all --apply
# 或者仅处理一个设备
sudo python3 /opt/aihub/enrollment/enable_pty.py --device demo-linux --apply
```

脚本只匹配云端保存的设备专属公钥，保留其他密钥及限制，修改前在目标机器 `.ssh` 中备份 `authorized_keys`。重复运行会跳过已启用的密钥；离线设备报告失败，可上线后重新执行。需要目标设备安装 Python（Linux 使用 python3，安卓使用 Termux 的 python）。Windows 旧设备暂不由此脚本处理。修改后重新创建网页终端，无需重启目标 SSH 服务。

- Linux远程工作已验证；Windows/安卓接入尚待完整实机测试。
- 已知上游插件热更新事务冲突未整体修复。
- 默认自签名证书，密码表单兼容 Origin:null，同时校验签名防伪令牌。
- 安装器拒绝覆盖既有部署；实际新环境端到端测试以当前任务验证结果为准。
- 下载和依赖安装需要可访问官方网络，可能受网络地区影响。

可设置 `AIHUB_DOWNLOAD_CACHE=/path/to/cache` 复用已下载的官方发行文件（按原下载文件名保存），用于慢速网络或测试。缓存应由管理员控制，Node仍会与官方SHA256清单比对；不要使用不可信缓存。
